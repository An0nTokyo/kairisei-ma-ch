# Android 微型服务端：阶段 C

## 目标

手机上可以启动和停止 Sm。启动后按网卡列出客户端能用的地址。登录回包使用客户端这次连上来的地址。未实现的请求得到降级响应，并且不写档。停止后账号文件仍在手机上。

本阶段不提供电脑地址、借出、交还，也不提供游戏内容。真实客户端若在登录前请求版本或资源，得到降级响应。

## 页面

两页。第一页是本机端口、启动、停止，以及启动后的地址列表。第二页标题为「查看日志」，内容是当前这次 Go 进程的标准输出和标准错误。这些输出同时追加写入应用目录的 `server.log`。再次启动时截断该文件，日志页只显示新进程的输出。

启动前没有 IP 输入。默认端口是 `26020`。允许的端口是十进制整数 `1` 到 `65534`，因为战斗端口是主端口加 `1`。未启动时才能修改端口，并写入应用目录的 `server-port`。启动后端口框锁定。

点地址列表中的一行，复制 `地址:端口`。页面不显示复制按钮，也不显示复制提示。列表只显示游戏端口。战斗端口不单独占一行。

## 进程

Kotlin 负责页面和前台服务。前台服务拉起 `kairi-mserver`。运行期间通知栏保留一条前台通知，点通知回到应用。离开页面不停止服务。只有停止按钮结束前台服务和 Go 进程。

`kairi-mserver` 监听 `0.0.0.0` 上的游戏端口和战斗端口。进程不接受对外公布地址的参数，手机上也不开放 Admin。数据目录是应用文件目录。本阶段不要求该目录里已有账号库。

Go 进程自行退出后，服务不再拉起它。页面回到未启动，通知撤掉，退出原因留在日志页。端口被占用或程序无法启动时同样回到未启动。玩家没有点停止、系统却杀掉前台服务时，服务按这次启动意图回来，并用 `server-port` 里的端口重新拉起进程。

## 地址列表

列表收录已经启用的网卡上的 IPv4 单播地址，每个地址一行。回环只保留 `127.0.0.1`，标签为「本机」，并带上该网卡的系统名。其余行使用网卡的系统名。

不收录 `0.0.0.0`、`169.254.0.0/16` 和 IPv6。枚举失败时服务继续运行。回环可用时，列表里至少有本机那一行。没有可用地址时列表为空，不填入假地址。网卡地址变化后刷新列表，不重启进程。

## 登录回包

登录由本阶段实现。主机取这次 TCP 连接在本机一侧的地址，忽略请求里的 Host 头。资源地址和服务器列表使用同一主机。战斗地址使用该主机和主端口加 `1`。

本机持有该账号时，回包沿用现有登录结果，只把其中的主机换成上面这个地址，并按现有流程更新会话。未知 UUID，以及账号存在但持有者不是本机时，返回 HTTP 200，`res_code` 为 `-1`，`res_str` 为「该账号不在这台手机上」。这两种情况都不分配 `user_id`，也不写档。

没有借出的账号时也可以启动服务。

## 降级与设备标识

除登录以外，本阶段的游戏路由进入同一个降级器。响应是 HTTP 200，`res_code` 为 `-1`，`res_str` 为「该功能需要连接电脑上的服务器」。降级不写账号库，也不删除游戏已下载的资源。

应用首次启动时，若 `device-id` 不存在，生成 UUID 并写入该文件。文件里已有合法 UUID 时沿用。文件存在但内容不是合法 UUID 时，不覆盖文件，也不启动服务，第一页显示原因。这个 UUID 是这台手机的持有者标识。

停止时，正在处理的请求随进程结束。停止不导出账号，也不删除应用目录里的账号文件。

## 测试

Go 包内测试覆盖：

- 降级响应使用固定文案，并且不写档。
- 登录成功时，回包主机等于这次连接的本机地址。测试在库里放入一个由本机 `device-id` 持有的账号。请求里的 Host 头使用另一个主机名，回包仍取连接的本机地址。
- 未知 UUID 不建号、不写档。账号存在但持有者不是本机时同样不写档。
- 地址列表包含标成「本机」的 `127.0.0.1`，也包含一块启用网卡上的 IPv4。列表排除 `0.0.0.0`、`169.254.0.0/16`、其他回环地址和 IPv6。
- 非法端口在拉起进程前被拒绝。
- 停止不删除账号文件。

Kotlin 只测试端口校验和地址整理。不要求模拟器。页面用手动确认。
